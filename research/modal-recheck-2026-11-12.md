### billing-models — partly — `$0.141912/core-hour`
Per second, on the higher of request and actual use. CPU $0.141912/core-hour and memory $0.024012/GiB-hour are the 3× non-preemptible sandbox rates. Requested resources bill for the sandbox's whole lifetime, so an idle sandbox pays its request. Disk is not a line: it raises the memory request at 20:1. GPU time is the exception — GPU sandboxes are preemptible and GPU is billed at standard, not 3×, rates.
· https://modal.com/docs/guide/sandbox-resources · "You're charged `max(request, actual)` for both CPU and memory." · https://modal.com/pricing · "Sandboxes are billed at non-preemptible rates of 3x list price."
**Changed:** yes (evidence quote). The old sentence "Modal Sandboxes are billed by the second based on whichever is higher: your resource request or your actual usage." is gone. The per-second part now lives on the pricing FAQ: "Functions and Sandboxes, billed by the second for CPU, memory, and GPU time." Rates unchanged. Note should add the lifetime-request sentence and the GPU exception.

**Changed:** note only. "No hosted agent, desktop, browser or computer-use API" is now misleading — say "No hosted agent or computer-use API; browser and desktop are bring-your-own (a documented VNC example)."

### custom-domains — yes — `Team+, manual`
Sandbox tunnels are served from `*.w.modal.host` by default. On Team and Enterprise you delegate a (sub)domain with NS records to Modal's nameservers, ask Modal on Slack to enable it, then pass `custom_domain=` at sandbox creation. The docs call the infrastructure production-grade but the onboarding a manual step.
· https://modal.com/docs/guide/sandbox-networking · "Custom domains for Sandbox tunnels are available on the Team and Enterprise plans." · "The infrastructure is production-grade, but onboarding requires a manual setup step."
**Changed:** no.

### idle-timers — partly — `5 min lifetime; no idle`
Default maximum lifetime is 5 minutes (SDK `timeout=300`); the ceiling is 24 hours. `idle_timeout` defaults to `None` and, when set, terminates rather than pauses. A sandbox counts as active while a command runs, stdin is written, or a tunnel TCP connection is open. There is no lifetime-free option: longer work needs a filesystem/memory snapshot and a new sandbox.
· https://modal.com/docs/guide/sandboxes · "Sandboxes have a default maximum lifetime of 5 minutes. You can change this by passing a `timeout` of up to 24 hours" · https://modal.com/docs/sdk/py/latest/Sandbox · "The amount of time in seconds that a sandbox can be idle before being terminated."
**Changed:** no.

### isolation — partly — `gVisor; VM on request`
Two runtimes: gVisor (default in practice; the SDK says leave `runtime` unset and "Modal pick") and a KVM-backed VM with its own Linux kernel, needed for Docker, FUSE, nested cgroups or a full Linux environment. Every container runs as root (uid 0); `USER` is ignored. GPU sandboxes are gVisor only. Up to 250 sidecar containers per sandbox give a second boundary. **New:** Modal is now a gVisor maintainer and says it launches upwards of 40 million gVisor containers a day.
· https://modal.com/docs/guide/sandboxes · "VMs run the Sandbox in a virtual machine with its own Linux kernel." · https://modal.com/docs/guide/existing-images · "Modal containers always run as root (uid 0)." · https://modal.com/blog/modal-gvisor-maintainer · "We launch upwards of 40 million gVisor containers a day."
**Changed:** note (gVisor maintainership; "Modal picks when unset" nuance). Verdict unchanged.

### keys-secrets — partly — `Env vars, or beta proxy`
Secrets are delivered as environment variables by default, so any process in the sandbox can read and print them. The beta Sandbox Secret Injection / Outbound Policy replaces headers on outbound HTTPS outside the sandbox, so the key never enters the environment; it is immutable per configuration and has known limitations. OIDC identity tokens are available (`include_oidc_identity_token=True`).
· https://modal.com/docs/guide/sandbox-secret-injection · "This replacement happens outside the Sandbox so the secret never appears in the Sandbox's environment."
**Changed:** no.

### lifecycle — no — `No pause; terminate`
Lifecycle is Created → Scheduled → Started → (Ready) → Finished. There is no paused, stopped, suspended or hibernated state. `terminate()` sends SIGKILL (code 137); a finished sandbox accepts no further commands. The nearest resume is a memory snapshot, which terminates the source and restores a new sandbox (7-day expiry). Exit snapshots capture the filesystem automatically on exit, not processes.
· https://modal.com/docs/guide/sandbox-snapshots · "Snapshotting a Sandbox will currently cause it to terminate."
**Changed:** no.

### outbound-network — yes — `$0.04/GiB`
Outbound is open by default. You can block all traffic, allow CIDR ranges, or allow domains (beta, TLS/443 only; SNI-based, ECH unsupported, DNS itself is unrestricted unless everything is blocked). Proxies (beta) give Team/Enterprise static egress IPs. Egress is $0.04/GiB over 1/10/100 TiB by plan, counted across the workspace; private container-to-container traffic and Cloud Bucket Mount uploads count, Volume reads/writes do not.
· https://modal.com/docs/guide/sandbox-networking · "By default, Sandboxes can make outbound connections to any public IP address." · https://modal.com/docs/guide/network-egress-billing · "Starting October 1, 2026, Modal charges for network egress."
**Changed:** note only (Proxies are beta; DNS sentence; bucket uploads count). Rates/allowances unchanged.

### reaching-it — yes — `Connect token`
Inbound is closed until a port is exposed. Encrypted and h2 tunnels use Sandbox Connect Tokens (`create_connect_token`, optional user metadata, `X-Verified-User-Data` header); unencrypted tunnels are raw TCP and accept anyone, and `inbound_cidr_allowlist` is not enforced on them. Tokens can go in `Authorization`, `_modal_connect_token` query param or cookie. **Catch:** a sidecar can reach the main container's token port directly and set any `X-Verified-User-Data` header, so the verified header is not a boundary against your own sidecar.
· https://modal.com/docs/guide/sandbox-networking · "You can make authenticated HTTP and WebSocket requests to a Sandbox by generating Sandbox Connect Tokens." · https://modal.com/docs/guide/sandbox-sidecars · "Sidecars bypass Connect Tokens: a Sidecar can reach the main container's Connect Token port directly and set any `X-Verified-User-Data` header."
**Changed:** note (sidecar caveat). Verdict unchanged.

### sizes-regions — partly — `No fixed sizes; 1 core = 2 vCPU`
No fixed shape menu: fractional physical cores (1 core = 2 vCPUs as documented) and MiB of memory, default 0.125 core / 128 MiB. CPU and memory accept `(request, limit)` tuples. Disk is a fixed 512 GiB quota (VM root filesystem fixed at 512 GiB), not resizable. The maximum shape is enforced but unpublished. Regions: broad `us`/`eu`/`ap` at 1.15×, narrow at 1.75×. GPU sandboxes are preemptible.
· https://modal.com/docs/guide/sandbox-resources · "The `cpu` parameter specifies physical CPU cores (1 core = 2 vCPUs), and `memory` specifies MiB" · https://modal.com/docs/guide/region-selection · "Broad (e.g. `us`) | 1.15x"
**Changed:** no. The CPU-unit dispute remains (see contradictions).

### snapshots-forks — partly — `Filesystem 30 d; memory 7 d`
Filesystem and directory snapshots are Images with a 30-day default TTL, configurable, `ttl=None` for indefinite. Memory snapshots capture disk + RAM + processes, expire after 7 days and cannot be extended, terminate the source, cannot run with GPUs, restore only on the same exact instance type, and cannot pin a region. Exit snapshots (beta) automatically capture the filesystem on graceful and ungraceful exit, retained 30 days. Forking means starting several sandboxes from one filesystem Image, not a live clone.
· https://modal.com/docs/guide/sandbox-snapshots · "Memory Snapshots expire 7 days after creation and cannot currently be extended." · https://modal.com/docs/guide/sandbox-exit-snapshots · "Exit snapshot Images are retained for 30 days after creation"
**Changed:** note only (exit snapshots beta; memory snapshot region/instance limits). Verdict unchanged.

### storage — partly — `512 GiB; billed as memory`
A fixed 512 GiB root filesystem per container, not resizable; requesting more disk raises the memory request at 20:1. Volumes are the durable option, survive the sandbox, are excluded from snapshots, and cost $0.09/GiB-month after 1 TiB free. **Volumes v1 is still the default**; v2 is opt-in (`version=2`), adds HIPAA, unlimited files, hundreds of concurrent writers, hard links and `sync` commits.
· https://modal.com/docs/guide/sandbox-resources · "On the VM runtime, the root filesystem is a fixed 512 GiB." · https://modal.com/docs/guide/volumes · "Volumes v1 is still the default when no version is specified, so pass `version=2`"
**Changed:** note only (v1 default / v2 opt-in). Price unchanged.

### teams-accounts — partly — `Environment budgets`

Team ($250/mo): unlimited seats, 5,000 containers, 50 GPU concurrency, 30-day logs, RBAC, service users, environment budgets, deployment rollbacks (3 versions), custom domains, static IP proxy. Enterprise: SSO (Okta/SAML), audit logs, HIPAA, custom limits. **Changed:** yes (scenario). "Starter has no budgets" is false — Starter has a workspace budget/spend limit. The differentiator is *environment*-level budgets, plus RBAC/service users.

### trials-free-tiers — partly — `$30/month credits`
Starter is $0 + compute with a recurring $30/month compute credit (not a one-off trial); Team is $250 + compute with $100/month. A payment method is required before anything runs. The credit covers Functions and Sandboxes; **Shared Endpoints tokens are billed separately from the first request and are not covered** (since 1 Sep 2026). Volumes include 1 TiB free; egress 1/10/100 TiB by plan.
· https://modal.com/pricing · "$30 / month free credits" · "It does not apply to Shared Endpoints, which are billed per token rather than per second."
**Changed:** note (Shared Endpoints exclusion). Verdict/credit unchanged.

### ways-to-drive — partly — `No; SDK`
Python, JavaScript/TypeScript and Go SDKs; a `modal` CLI; `modal shell` (attach by sandbox ID or container ID, PTY); a dashboard with per-App sandbox metrics and exit reasons; `modal skills` installs official agent skills for coding assistants. No documented REST/HTTP API separate from the SDK/gRPC surface, no SSH daemon, no control-plane MCP server. `modal shell` is a CLI session, not SSH.

**Changed:** note (`modal skills`). Verdict unchanged.

## 4. First-party contradictions (both sides quoted)

**4.1 "Never pay for idle" vs sandboxes bill the request.**
- Pricing headline: "You never pay for idle resources — just actual compute time, by the CPU cycle." — https://modal.com/pricing
- Same page, sandbox FAQ: "It's important to use the average resource consumption instead of the peak because Modal Sandboxes are charged based on the max(request, usage)." — https://modal.com/pricing
- Docs: "You are charged for requested resources for the lifetime of your Sandbox, regardless of whether the resources are being used." — https://modal.com/docs/guide/sandbox-resources

*Model interpretation:* the headline describes scale-to-zero Functions; a Sandbox with no active command still bills its request until terminated. Keep all three quotes; use the sandbox line for the card.

**4.2 Sandbox disk cannot be increased vs 3.0 TiB maximum.**
- "Sandboxes have the same disk limits as other Modal containers, and their disk size cannot be increased. On the VM runtime, the root filesystem is a fixed 512 GiB." — https://modal.com/docs/guide/sandbox-resources
- "Increased disk sizes can be requested with the `ephemeral_disk` parameter on `@app.function()`. The maximum disk size is 3.0 TiB (3,145,728 MiB)." — https://modal.com/docs/guide/resources

*Model interpretation:* 512 GiB is the Sandbox ceiling; `ephemeral_disk` is a Function parameter. The first sentence's "same disk limits as other Modal containers" is the confusing part, not a second sandbox size.

**4.3 One core is two vCPUs vs one guest CPU.**
- "The `cpu` parameter specifies physical CPU cores (1 core = 2 vCPUs), and `memory` specifies MiB" — https://modal.com/docs/guide/sandbox-resources
- "1 Modal core = 1 vCPU" — https://battleships.dev/data/providers/modal.md (third-party; battleships.dev is built by the Boat team, one of the providers compared here)

*Model interpretation:* keep both. The documented reading gives A $39.66, B $347.42, C $21.42; the measured reading gives $63.31, $554.61, $34.19. This is a third-party disagreement, not a Modal self-contradiction, but it is the largest uncertainty in any Modal total.

**4.4 Runtime is gVisor by default vs Modal chooses when unset.**
- "Switch runtimes via the `runtime` parameter, or leave unset to let Modal choose for you." — https://modal.com/docs/guide/sandboxes
- "To force continued use of the gVisor runtime, set `runtime="gvisor"`. This is the current default behavior, but the default may change in the future." — https://modal.com/docs/sdk/py/releases

*Model interpretation:* gVisor is what Modal currently chooses, but the guarantee is "Modal chooses", not "gVisor". Say "currently gVisor" in prose, not "gVisor by default" as a contract.

**4.5 Status page 100% for 30 days vs a 23-minute degradation two days ago.**
- "Sandboxes 100% uptime 99.983% uptime 99.989% uptime" — https://status.modal.com
- "Some Sandboxes experiencing creation failures — Degraded for 23 minutes — Nov 10, 2026" — https://status.modal.com

*Model interpretation:* the 30-day column is availability, not incident-free time; a degradation can sit inside a 100% bar. Read the incident list, not just the percentage.

### Scope tensions (not strict contradictions)

**4.6 3× "non-preemptible" sandbox price vs preemptible GPU sandboxes.**
- "Sandboxes are billed at non-preemptible rates of 3x list price." — https://modal.com/pricing

*Model interpretation:* 3× applies to CPU and memory; GPU sandboxes are preemptible and GPU time is at standard rates. The first sentence is scoped too loosely for a reader who skims.

## 7. Judgment calls and unresolved questions

**Judgment calls made (parent may override):**

1. **`browser` / `desktop` = `partly`, not `yes`.** The example builds Chromium/Xvfb/x11vnc/noVNC itself; nothing is in the default image and there is no browser/desktop API. `partly` matches Morph ("documented example runs headless Chrome") and Freestyle ("guide builds GNOME with TigerVNC and noVNC"). If the site reserves `partly` for provider-managed surfaces only, keep `no` and move the example to the note.
2. **`usage-alerts` = `partly`, not `yes`.** The feature exists but only through a beta Slack integration, requires a Workspace Manager, and has no email/in-dashboard threshold. `partly` matches the site's beta treatment elsewhere (`hidden-secrets`).
3. **`scoped-keys` stays `partly`.** Service users are a real scoped key, but Team/Enterprise only; `partly` matches the plan-gate convention (`custom-domain`, `static-ip`).
4. **`tunnel` stays `not-published`.** Modal's Tunnels are public URLs/raw sockets, not localhost port forwarding. An installed SSH server would give `ssh -L`, but that is DIY and not documented as a tunnel feature. If the parent prefers "reachable from your computer" literally, `partly` is defensible.
5. **`schedules` stays `yes`.** The 5-cron Starter cap is a plan limit, not a missing capability; note it rather than downgrade.
6. **`company` stays `partly`.** No public SLA still; SOC 2 and funding are strong, but the missing SLA is the shortfall.
7. **`own-vm` stays `partly`.** VM is opt-in; "Modal picks when unset" does not make the default a VM.

**Unresolved / not published:**

- Maximum Sandbox CPU and memory shape (a maximum is enforced; no number).
- Snapshot storage price (filesystem, directory, memory, exit).
- Public SLA text, uptime target and credit regime.
- GPU preemption frequency, notice and checkpoint behavior.

- Whether the $30/$100 credit covers Volume storage above 1 TiB (pricing FAQ separates "compute" from "Volumes include up to 1 TiB free"; likely not, but not stated).

- Taxes and currency (USD list; no tax statement).
- `desktop` end-to-end: the documented agent drives Chromium over CDP, not the X desktop. A true computer-use agent clicking the VNC screen is not benchmarked here.
